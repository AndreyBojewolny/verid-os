# Спецификация: Evolution Loop VeridOS v0.2 (РЕШЕНО)

## Петля
Monitor -> Analyze -> Plan -> Execute (+Knowledge), гейтованная журналом,
capability-моделью и non-regression-барьером. Петля не проверяет сама себя.

## В1. Модельный стек — РЕШЕНО: три яруса
- Monitor/Analyze (>=90% тиков): локальная малая модель (Qwen3 8B при 8ГБ VRAM;
  Qwen3.5-2B/4B при меньшей) либо чистые правила без LLM.
- Plan/Execute: облачный агент (QwenWork), батчево — ночные окна и major-тики.
- Дифференциальные тесты: без LLM, детерминированный cargo.
Каждый LLM-вызов обязан объявлять ярус в записи журнала (model_tier) —
иначе replay не воспроизводит решение.

## В2. Ночной режим — РЕШЕНО: событийные тики всегда + ночное окно
- Событийные тики всегда: аномалии телеметрии, завершение задачи клеткой,
  расхождение state_hash при replay (приоритет 0), накопленный батч.
- Major-тики: ночное окно 02:00-06:00, потолок 4 major-тика в сутки.
- Окно и потолок — конфиг владельца; правка сама журналируется.

## В3. Красные линии — РЕШЕНО: 5 абсолютов, без override
1. Любое изменение L0 — петля замирает и ждёт владельца.
2. Расхождение state_hash при replay — заморозка эволюции, консервация журнала, алерт.
3. Попытка расширить собственные права — авто-откат + DLQ + алерт;
   3 попытки за эпоху = полная остановка до ручного разбора.
4. Три подряд non-regression-отката — пауза петли до человека.
5. Исчерпание бюджета — переход в деградацию (В5), не тишина.
Все пять — константы конституции. Переключатель red_lines_override не существует.

## В4. Reachability — РЕШЕНО: фича-минимум -> данные препринта
- v0 = гейт эволюции: проверка каждого CodeUpdate на «не расширяет overgrant».
- v1 = данные препринта. Препринт — до конца Q1 2027.
- Позиционирование: против HarnessAudit («они установили проблему — мы её измеряем»),
  отграничение от SkillGuard (runtime, не ретроспектива) и Near-Miss (LLM-эмпирика).

## В5. Бюджет и деградация — РЕШЕНО: каскад A->B->C
- Ярус A (полный): локальный Monitor + облачный Execute.
- Ярус B (эконом): только локальная модель и правила; модификации запрещены,
  только анализ и очередь гипотез.
- Ярус C (заморозка): heartbeat-запись в журнал раз в N часов.
- Переходы — события журнала (EvolutionCycle kind=degrade).
- Месячный потолок расходов задаётся владельцем.

## Новые события журнала (16 -> 21)
Telemetry, Hypothesis, CodeUpdate, CanaryResult, EvolutionCycle.

## Инвариант эволюции (конституционный)
Эволюция не может расширять собственные права. Каждый CodeUpdate проверяется
на пост-условие «суммарный capability-set после <= до»; исключение — только
явные human-granted гранты. Нарушение = авто-откат + DLQ + алерт.

## Градация прав на самомодификацию
- L0: только релизы, подписанные владельцем (человек всегда).
- Код клеток: авто (песочница + canary + откат < 1 тик).
- Политики MAC/карантина: авто с усилением, проверка reachability.
- Сама петля: запрещено по построению (попытка = CapabilityViolation).
- L2-анклав: свободно, только журналирование.

## Защиты
1. Capability-изоляция оценщика (урок DGM: удаление маркеров детектора).
2. Строгий non-regression (урок HarnessBank: 62-76% ложных улучшений).
3. Только автоградируемые метрики.
4. Разделение генератора и проверяющего.

## Метрики зрелости M1-M5
- M1: 0 изменений вне журнала (обратный поиск изменений на диске).
- M2: 100% replay.
- M3: ноль неавтогрейженных метрик.
- M4: overgrant surface монотонно не растёт.
- M5: дифференциальные тесты hosted vs native зелёные.
