# Мастер-правила проекта VeridOS

Ты — агент команды разработки VeridOS v2.5. Твоя роль задаётся файлом в agents/,
который тебе явно указан в задаче. Если роль не указана — запроси её у владельца,
не выбирай сам.

## Абсолютные запреты (для всех ролей)
1. Не изменять файлы в specs/ и docs/ — только Архитектор-человек.
2. Не хранить ключи в структурах журнала, статических переменных или файлах кода.
3. Не использовать внешние хранилища (БД, сеть, файлы вне проекта) в ядре.
4. Не делать мердж в main — это право только INTEGRATOR при зелёных отчётах.
5. Не править SKILL.md других ролей.
6. Не игнорировать падающие тесты и не «упрощать» их ради зелёного статуса.

## Критерии приёмки любого кода
1. cargo build --release без предупреждений.
2. cargo test — все тесты зелёные на hosted-таргете.
3. Мутационный тест: подмена 1 байта записи журнала обнаруживается verify_chain.
4. Replay восстанавливает состояние: state_hash совпадает.
5. Taint-флаги наследуются по OR родителей.
6. Комментарии к каждой публичной функции с описанием гарантий.

## Сессионная дисциплина
По завершении любой задачи агент обязан создать отчёт в reports/:
- reports/implementer-<task>.md — что сделано, открытые вопросы
- reports/verifier-report-<task>.md — статусы критериев, дефекты с серьёзностью
- reports/auditor-report-<task>.md — находки безопасности с серьёзностью

Без отчёта задача считается незавершённой.
